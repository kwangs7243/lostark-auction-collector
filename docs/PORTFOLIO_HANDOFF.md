# 포트폴리오 준비 및 개발 인수인계

이 문서는 집에서 진행한 프로젝트를 학원 컴퓨터와 새로운 Codex 세션에서 이어가기 위한 개발·학습 가이드입니다. 이전 대화 내용이 없어도 프로젝트의 배경과 현재 상태를 파악할 수 있도록 작성했습니다.

## 1. 프로젝트 성격

이 프로젝트는 로스트아크에서 융화 재료를 제작할 때 필요한 재료와 최저비용 조달 계획을 계산하는 개인용 웹 도구입니다.

개발자는 실제 게임 사용 과정에서 문제를 정의하고 다음 의사결정을 직접 내렸습니다.

- 보유 재료는 이미 지출한 자원이므로 기본 추천 기준인 `실제 추가 지출`에서 제외한다.
- 거래소의 묶음 구매와 게임 내 교환 단위를 모두 지켜야 한다.
- 단순 환산 단가가 아니라 실제로 실행 가능한 완성된 후보 플랜의 비용을 비교한다.
- 구현 복잡도에 비해 효용이 낮은 목재·튼튼한 목재 혼합 구매는 범위에서 제외한다.
- 개인 사용 빈도를 고려해 AJAX 상태 관리 대신 Flask 서버 렌더링 구조를 유지한다.
- API 최저가가 소량 매물일 수 있으므로 사용자가 계산 적용 가격을 직접 수정할 수 있게 한다.

Codex는 구현, 테스트 작성, UI 구성과 문서화를 보조했습니다. 포트폴리오 준비의 다음 목표는 코드를 개발자 본인이 설명하고 수정할 수 있는 수준으로 이해하는 것입니다.

### 재료 조달

- 부족 재료 직접 구매
- 목재 직접 구매와 튼튼한 목재 교환 비교
- 목재 또는 부드러운 목재를 생활의 가루로 교환
- 보유 잉여 재료 혼합 교환
- 제작용 재료와 교환용 재료를 합산한 묶음 구매 계산
- 구매·교환·제작 후 남는 재료 표시

### 분석 정보

- 실제 추가 지출
- 보유 교환 재료의 시장가치
- 목재와 부드러운 목재 교환 후보 비교
- 각 재료의 교환 횟수, 사용량, 획득 가루와 잔여 가루

## 4. 반드시 유지할 도메인 규칙

```text
목재 100개         → 생활의 가루 80개
부드러운 목재 50개 → 생활의 가루 80개
생활의 가루 100개  → 아비도스 목재 10개
튼튼한 목재 5개    → 목재 50개
```

- 목재, 부드러운 목재, 튼튼한 목재, 아비도스 목재는 거래소에서 100개 단위로 구매한다.
- 구매 수량은 실제 부족량을 기준으로 100개 단위 올림 처리한다.
- 완제품 융화 재료는 개당 가격으로 구매한다.
- 튼튼한 목재는 5개 단위로만 사용하고 목재는 50개 단위로 획득한다.
- 보유 재료는 실제 추가 구매 비용에 포함하지 않는다.
- 제작용과 교환용으로 같은 재료가 필요하면 합산한 뒤 한 번만 구매 단위를 적용한다.
- 목재 조달은 부족한 목재 전량 직접 구매와 전량 튼튼한 목재 교환을 비교한다.
- 현재 최저가와 최근가 중 큰 값을 사용하던 보수 계산은 제거되었다. 초기 가격은 `CurrentMinPrice`만 사용한다.
- 최종 계산 가격은 화면에서 사용자가 제출한 값이다.

## 5. 코드 흐름

```text
브라우저 폼 입력
    ↓
web_app.index
    ↓
입력값·가격 검증
    ↓
필요 재료와 부족 재료 계산
    ↓
여러 구매·교환 후보 생성
    ↓
후보별 실제 구매 단위와 총비용 계산
    ↓
최저비용 플랜 선택
    ↓
화면용 요약 데이터 생성
    ↓
Jinja 템플릿 렌더링
```

주요 모듈 책임:

| 파일 | 역할 |
|---|---|
| `web_app.py` | Flask 요청 처리, 입력 검증, 계산 결과의 화면용 변환 |
| `src/constants.py` | 레시피, 교환 비율, 가격 입력 대상 |
| `src/material_utils.py` | 필요량, 부족량, 잔여량, 재료 가치 계산 |
| `src/exchange_calculator.py` | 생활의 가루와 아비도스 목재 교환 계획 |
| `src/purchase_calculator.py` | 직접 구매, 튼튼한 목재, 교환용 구매 후보 계산 |
| `src/plan_calculator.py` | 제작 가능한 전체 후보 플랜 조립 |
| `src/plan_selector.py` | 실제 추가 지출과 재료 가치 기준 최종 플랜 선택 |
| `src/market_prices.py` | 계산에 필요한 거래소 품목 조회 |
| `src/price_utils.py` | 현재 최저가 가격표와 교환 단가 계산 |
| `tests/test.py` | 계산 경계값과 Flask 렌더링 회귀 테스트 |

## 6. 개발자가 우선 공부할 순서

전체 코드를 한 번에 읽지 말고 다음 순서로 진행합니다.

### 1회차: 웹 요청 흐름

읽을 파일:

- `main.py`
- `web_app.py`
- `templates/index.html`

목표:

- GET과 POST에서 API 조회 시점이 어떻게 다른지 설명한다.
- 화면 가격이 계산 함수로 전달되는 과정을 추적한다.
- 계산 결과가 템플릿 데이터로 바뀌는 위치를 찾는다.

### 2회차: 재료와 교환 계산

읽을 파일:

- `src/constants.py`
- `src/material_utils.py`
- `src/exchange_calculator.py`

목표:

- 제작 횟수가 필요 재료로 변환되는 과정을 설명한다.
- 가루와 아비도스 목재의 교환 횟수 올림을 직접 계산한다.
- 보유 재료에서 제작용 재료를 먼저 남겨두는 이유를 설명한다.

### 3회차: 구매 후보와 플랜 선택

읽을 파일:

- `src/purchase_calculator.py`
- `src/plan_calculator.py`
- `src/plan_selector.py`

목표:

- 목재 직접 구매와 튼튼한 목재 교환 후보를 비교한다.
- 제작용·교환용 수요가 어느 함수에서 합쳐지는지 찾는다.
- 여러 제작 플랜 중 추천 플랜이 선택되는 기준을 설명한다.

### 4회차: 테스트

읽을 파일:

- `tests/test.py`

목표:

- 각 테스트가 방어하는 실제 게임 규칙을 한 줄로 요약한다.
- 100개와 101개 부족의 차이를 설명한다.
- 과거에 발견한 제작용·교환용 목재 분리 문제를 재현하는 테스트를 찾는다.

## 8. 다음 Codex 세션의 작업 원칙

이 프로젝트는 포트폴리오 준비와 개발 학습을 함께 진행합니다. 다음 Codex는 기능을 대신 구현하는 것만 목표로 삼지 말고 개발자가 코드를 이해하도록 도와야 합니다.

- 작업 시작 전에 `README.md`와 이 문서를 읽는다.
- 전체 파일을 무조건 다시 읽지 말고 현재 작업에 필요한 파일부터 확인한다.
- 코드 수정 전 변경할 파일, 함수, 계산 흐름을 먼저 설명한다.
- 핵심 로직을 수정할 때는 개발자가 먼저 예상 결과를 말할 기회를 준다.
- 기존 기능과 서버 렌더링 구조를 임의로 제거하거나 대규모 리팩터링하지 않는다.
- 계산 규칙 변경에는 경계값 테스트를 함께 추가한다.
- 구현 후에는 변경 내용뿐 아니라 개발자가 알아야 할 코드 흐름을 설명한다.
- AI가 작성한 코드를 그대로 신뢰하지 않고 실제 수치와 테스트로 검증한다.
- Git 작업은 기능, 디자인, 문서처럼 의미 있는 단위로 커밋한다.
